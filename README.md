# Stone Age Chronicles

스톤에이지에서 영감을 받은 웹 기반 펫 포획·육성 턴제 RPG.
같은 종의 펫이라도 **성장률**과 **원소 배분**이 개체마다 달라서, 조금이라도 더 좋은
개체를 찾아 포획하고 육성하는 것이 핵심 재미입니다.

## 실행

```bash
cd client
npm install
npm run dev      # http://localhost:5173
npm run build    # 타입체크 + 프로덕션 빌드
```

## 구현 범위

### 개체차 — 이 게임의 핵심

같은 종을 잡아도 두 축에서 개체가 갈립니다.

- **성장률**: 6개 스탯(STR·AGI·VIT·SPA·SPD·LCK)이 각각 독립적으로 0.85~1.15배를
  가집니다. 피라미드형 등급 분포(최하위급 14% ~ 최상위급 1%)에 서버 전설 개체
  (1.20배 이상, 확률 0.0000044%)가 별도로 존재합니다.
- **원소 배분**: 4원소에 10포인트를 나눠 가집니다. 화10 순혈부터 화6수2지1풍1까지
  같은 종에서 34가지 이상의 배분이 나옵니다. 배분은 상성 계산과 자속성 보정에
  직접 들어가므로 전투력에 실제로 영향을 줍니다.

### 전투

- 턴제. 속도와 스킬 우선도로 행동 순서 결정
- **테이머 참전**: 펫과 함께 싸우고, 펫이 전멸해도 테이머가 홀로 버팁니다 (3턴 쿨다운)
- **상태이상** 5종: 독·마비·수면·화상·동결. 행동 불가, 지속 피해, 물리 공격력 감소
- 상성 예측을 스킬 버튼에 미리 표시 (효과 굉장 / 유리 / 불리 / 효과 미미)
- 크리티컬, 방어, 교체, 도망
- 펫 모션 6종(idle·walk·attack·hurt·faint·victory)을 프레임 수·시간 스펙대로 구현
- 턴 연출 2단계: 공격 모션(380ms) → 임팩트·데미지 표시(520ms)
- CRITICAL! / SUPER EFFECTIVE! / RESISTED 표시, 데미지 숫자 색상·크기 구분
- 속성별 입자 이펙트, 화면 흔들림·섬광, 지역별 전투 배경
- AI 난이도 3단계(easy/normal/hard). 보스·PvP는 hard로 상태이상까지 노린다
- 모든 연출은 `prefers-reduced-motion` 대응

### 육성

- 레벨업으로 스킬 습득, 4슬롯 내에서 자유 편성
- **진화**: 레벨 + 진화석. 성장률과 원소 배분을 그대로 유지한 채 기본 스탯만 상승하므로
  개체의 우열이 진화 후에도 이어집니다 (시뮬레이션 검증 96%)
- 별명 지정, 팀(최대 5)/보관함, 포션

### 필드 탐험

- 타일 기반(32px) 필드 맵. 방향키·WASD·화면 D패드로 캐릭터 이동(타일당 200ms)
- 지역별 맵 크기 800×608 ~ 1184×992px, 카메라가 플레이어를 따라가며 경계에서 고정
- 지형은 지역 시드에서 결정적으로 생성. 도로를 깔고 도달 가능성 검사를 돌려
  **전 지역 도달률 100%**를 보장한다
- 수풀을 걸으면 야생 조우, 보물상자 5~15개, NPC 대화, 마을·던전 입구
- 보이는 타일만 그려 큰 맵에서도 그리는 양이 일정 (측정 61 FPS)

### 사운드

오디오 파일 없이 Web Audio API로 합성한다. 저장소에 바이너리가 없고 오프라인에서도
동작한다. 속성별 공격음(불 타닥 / 물 철렁 / 흙 쿵 / 바람 휘이잉), 피격·크리티컬·
약점·상태이상·포획·승리·패배·UI 효과음과 지역별 BGM 7종. 설정에서 음소거·음량 조절.

### 콘텐츠

- **5개 지역**: 푸른 초원(1~20) · 울창한 숲(15~35) · 험준한 산맥(30~50) ·
  불타는 화산(45~65) · 신비한 빙산(60~80)
- 지역마다 마을 · 필드 · 던전. 던전 보스를 잡으면 다음 지역이 열립니다
- **펫 42종** (기본형 · 진화형 · 희귀 · 보스), 각 종마다 고유 SVG 아트
- 도감(지역별 분류, 미포획 실루엣, 종별 최고 성장률 기록)
- PvP 아레나(랭킹 점수 · 티어), 상점, localStorage 자동 저장

## 스프라이트 시트 대신 SVG를 쓴 이유

완성도 가이드는 펫마다 128×128px PNG 스프라이트 시트 24프레임(6모션 × 4프레임)을
요구합니다. 42종이면 1,008프레임의 픽셀 아트가 필요한데, 이건 코드로 생성할 수
있는 결과물이 아닙니다.

같은 목표(6종 모션)를 SVG + CSS 키프레임으로 달성했습니다. 가이드 3.1~3.2절의
프레임 수와 지속시간(Idle 4×200ms, Walk 6×150ms, Attack 8×100ms, Hurt 3×100ms,
Faint 4×200ms, Victory 6×200ms)을 그대로 따랐고, Idle·Walk는 `steps()`로
프레임 단위 재생을 해 스프라이트 시트와 같은 질감이 납니다. 42종 전부에 추가
에셋 없이 적용되고, 나중에 실제 스프라이트 시트가 준비되면 `PetSprite` 내부만
교체하면 호출부는 그대로입니다.

## 펫 아트에 관해

`components/PetSprite.tsx` 한 파일에 42종의 SVG가 들어 있습니다. 이미지 파일을
쓰지 않은 이유는 "형상 × 속성" 구조 때문입니다. 같은 형상이라도 원소 배분에 따라
색이 달라야 하는데, SVG로 그리면 대표 원소 색 하나로 자동 착색되므로 형상 42종 ×
속성 4종을 파일 168개로 관리할 필요가 없습니다. 도감의 미포획 실루엣도 같은
소스에 `silhouette` 플래그만 넘겨 처리합니다.

새 펫을 추가할 때는 `petData.ts`의 `PET_SHAPES`에 종을 넣고 `PetSprite.tsx`의
`ART` 맵에 같은 `id`로 아트를 추가하면 됩니다. 아트가 없으면 1번 형상으로
대체되므로 데이터만 먼저 넣어도 깨지지 않습니다. 나중에 일러스트로 교체하려면
`PetSprite` 내부만 바꾸면 되고, 호출부는 손대지 않아도 됩니다.

## 설계 문서와 다르게 구현한 부분

기획 문서(`docs/game-design.md`)를 그대로 구현했을 때 플레이가 성립하지 않아
조정한 항목입니다. 근거 수치는 모두 실제 게임 코드로 시뮬레이션해 측정했습니다.

### 1. 상성표를 균형 사이클로 교체

문서 5.3의 표는 대칭이 아닙니다. 그대로 구현하면 이렇게 됩니다.

| 속성 | 공격 유리 | 공격 불리 | 방어 약점 | 방어 저항 | 종합 |
|------|----------|----------|----------|----------|------|
| 수 | 화, 풍 | 지 | 지 | 화, 풍 | **+2** |
| 풍 | 화, 지 | 수 | 수 | 화, 지 | **+2** |
| 화 | 지 | 수, 풍 | 수, 풍 | 지 | **-2** |
| 지 | 수 | 화, 풍 | 화, 풍 | 수 | **-2** |

사이클이 아니라 계층입니다. 화 속성은 수·풍 양쪽에 2배로 맞으면서 유리한 상대는
지 하나뿐이라, 화 속성 스타터의 첫 전투 승률이 **33%**까지 떨어졌습니다
(다른 스타터는 64~67%).

**화 > 풍 > 지 > 수 > 화** 순환으로 바꿔 네 속성이 각각 유리 1·불리 1·약점 1·저항 1을
갖도록 했습니다. 배수(2.0 / 1.0 / 0.5)와 배분 가중 합산 방식은 문서 그대로입니다.
수정 후 스타터 승률은 55.2% / 59.3% / 62.1%로 수렴했습니다.

### 2. 데미지 공식에 레벨 스케일링 추가

문서 5.4의 `공격력 × 위력 / 방어력`을 그대로 쓰면 Lv.1 기준 한 번의 공격이
95 데미지인데 Lv.1 펫의 최대 HP는 35~65라, **선공권을 잡은 쪽이 무조건 1턴에
이기는** 상태가 됩니다.

```
기본 데미지 = (레벨계수 × 위력 × 공격력 / 방어력) / 50 + 2
레벨계수  = 2 × 공격자레벨 / 5 + 2
```

상성 배수와 크리티컬 배수를 곱하는 최종 계산은 문서 그대로입니다.
수정 후 지역별 평균 전투 길이는 6.4 / 5.1 / 5.1 / 5.2 / 4.2턴입니다.

### 3. 상성 계산을 양방향으로 일반화

문서 5.3의 예시는 공격자만 배분을 갖고(화9수1) 방어자는 단일 속성(지10)입니다.
실제로는 양쪽 다 배분을 가지므로 이중 합으로 일반화했습니다.

```
배수 = Σ(공격원소) Σ(방어원소) 상성[공][방] × 공격비율 × 방어비율
```

문서 예시를 이 식에 넣으면 문서와 같은 값이 나옵니다.

### 4. 스타터 기본 스탯 조정 및 성장률 하한

`HP = VIT × 5 + 10` 구조상 VIT가 다른 스탯보다 훨씬 무겁게 작용해, 기본 스탯
총합이 같아도 VIT가 낮은 종이 크게 밀립니다. 스타터 3종의 VIT를 7~8로 맞췄습니다.

또한 첫 파트너는 평균 성장률 0.98 이상인 개체만 제시합니다. 전체 분포 평균이
0.953이라 하한이 없으면 최하위급 스타터로 시작해 초반이 막힐 수 있습니다.

### 5. 초반 조우 보정

플레이어 레벨 5 미만 구간에서는 필드에 common 등급만, 플레이어 레벨 이하로만
출현시킵니다. 보정 전 Lv.1 스타터의 첫 야생 전투 승률은 17~59%였습니다.

### 6. 테이머 능력치를 펫보다 낮게

테이머는 펫이 전멸한 뒤에도 계속 싸우기 때문에, 펫과 비슷한 HP를 주면 사실상
체력이 두 배가 됩니다. 초기 구현에서는 초반 승률이 93~100%까지 올라가 전투가
무의미해졌습니다. VIT 계수를 펫의 절반 수준으로 낮춰 "한 번 더 버틸 기회"에
그치도록 했습니다.

## 검증

`npm run build`(타입체크 포함)와 `oxlint` 에러 0건 외에, 실제 게임 코드로
시뮬레이션과 브라우저 플레이테스트를 돌렸습니다.

- 상성표 대칭성: 네 속성 모두 종합 0
- 스타터 첫 전투 승률(펫 대 펫, N=1500): 55.2% / 59.3% / 62.1%
- 지역별 동레벨 평균 전투 길이(N=400): 6.4 / 5.1 / 5.1 / 5.2 / 4.2턴
- 원소 배분 다양성: 한 종에서 34가지
- 진화 전후 개체 우열 유지: 96%
- 브라우저(Playwright): 스타터 → 상점 → 야생 전투 → 상성 예측 표시 → 테이머 공격 →
  포획 → 스킬 편성 → 진화(성장률 유지 확인) → 도감 → 보스전 → 지역 해금 →
  새로고침 후 저장 유지. 콘솔 에러 0건
- 상태이상: 자장가로 수면 부여 후 포획 성공률 52%로 상승(1.5배 보정) 확인
- 보스전 패배 시 지역이 해금되지 않는 것 확인

필드·연출·접근성(완성도 가이드 8절 체크리스트):

- 필드 61 FPS, 전투 61 FPS (목표 60)
- 전 지역 스폰 도달률 100%, 배치된 오브젝트 전부 접근 가능
- 키보드 이동 정확도: 스폰 (12,15)에서 위 6칸·왼쪽 6칸 → (6,9)
- 보물상자 획득(골드 500→1000)과 재접촉 시 중복 지급 없음, NPC 대화, 마을 진입
- 재생 확인된 모션·이펙트: pet-idle, pet-attack, pet-hurt, 속성 입자,
  CRITICAL!, SUPER EFFECTIVE!
- 최저 색상 대비 11.49:1 (가이드 기준 4.5:1)
- D패드 버튼 44×44px (가이드 최소치)
- 360×640 / 768×1024 / 1280×800 전부 가로 오버플로 없음
